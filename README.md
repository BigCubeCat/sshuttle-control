# Shuttle Control

Графическая оболочка для запуска `sshuttle` на Nura (postmarketOS).

Интерфейс написан на Qt Quick + Kirigami, логика — на C++20.

## Зависимости

1. Qt 6 (Core, Gui, Qml, Quick, QuickControls2, Network)
2. KDE Kirigami для Qt 6
3. CMake
4. Для подключения с паролем нужен `sshpass`;
5. для диагностики - `ping`.
6. Для повышения прав доступны `pkexec` (с работающим polkit-агентом) или `sudo`.

На Arch Linux зависимости обычно устанавливаются так:

```sh
sudo pacman -S --needed base-devel cmake extra-cmake-modules qt6-base qt6-declarative kirigami qqc2-desktop-style
```

## Сборка

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
./build/shuttle-control
```

Установка для текущего пользователя не настроена в виде пакета; executable можно запускать из `build/`. Desktop-файл лежит в `packaging/`.

## Первоначальная настройка

1. Откройте меню приложения → «Настройки».
2. Введите IPv4 сервера и SSH-логин.
3. Укажите **абсолютный путь** к вашей команде, например `/home/USER/bin/shuttle/run`. Не оставляйте относительный путь `./bin/shuttle/run`: приложение запускается из каталога, заданного путём к команде, а не из того каталога, в котором вы вручную набрали команду.
4. Введите SSH-пароль либо укажите файл, в котором первая строка содержит пароль. Если ввести пароль в поле приложения, он сохраняется в отдельный файл `ssh_password` с правами только владельца (0600); пароль не помещается в `QSettings`.
5. Выберите способ повышения прав. `pkexec` требует установленный polkit и работающий графический агент авторизации. `sudo -n` сработает только если `sudo` уже настроен на беспарольный запуск команды; приложение специально не пытается открывать интерактивный терминальный запрос sudo.
6. При необходимости включите DNS через туннель и настройте адрес ping.

## Безопасность пароля

Файл с паролем содержит секрет в открытом виде, даже если права доступа установлены в `0600`. Не сохраняйте его в публичном/синхронизируемом каталоге и не добавляйте в Git. Более безопасный вариант — SSH-ключ и отключённая/пустая настройка файла пароля. Если используется внешний `.txt`, приложение не меняет права этого внешнего файла.

## Ограничения первой версии

- Статус туннеля отражает процесс, запущенный этой копией приложения; туннель, запущенный вручную до открытия GUI, не обнаруживается.
- Скорость - это текущий объём трафика в байтах в секунду на интерфейсе маршрута по умолчанию, а не результат теста пропускной способности.
- Проверка ping независима от процесса sshuttle: успешный ping сам по себе не доказывает, что трафик прошёл именно через туннель.
- Приложение не проверяет автоматически IPv6-маршрутизацию. Конфигурация `0/0` маршрутизирует IPv4; перенаправление DNS соответствует флагу `sshuttle --dns`.
- Конфигурация сделана как стартовый проект и требует проверки сборки и тестирования непосредственно на используемой версии postmarketOS / Plasma Mobile.
